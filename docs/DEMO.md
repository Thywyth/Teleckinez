# Сценарій демонстрації на захисті (3–4 хв)

Усе працює без інтернету: брокер, моделі, веб-панель — локально. Відповіді
асистента в таблицях нижче взяті з реального прогону
(`presentation/record_demo.py`, 03.11.2026), тож на захисті мають бути
такими самими.

## Підготовка (за 10–15 хв до виступу)

1. Ноутбук на зарядці, режим живлення «Найкраща продуктивність» (відеокарта
   не засинає), Wi-Fi можна вимкнути — асистенту він не потрібен.
2. Відкрити PowerShell у папці проєкту й активувати середовище:

   ```bash
   .venv\Scripts\activate
   ```

3. Перевірити, що все на місці — моделі, мікрофон, динамік, брокер, порти,
   відеокарта. Усі рядки мають бути з ✓ (Ollama може бути «!» — для показу
   вона не потрібна):

   ```bash
   python scripts/preflight.py
   ```

4. Запустити все однією командою (брокер → симулятор → асистент →
   браузер з веб-панеллю):

   ```bash
   powershell -ExecutionPolicy Bypass -File scripts\demo.ps1
   ```

   Дочекатися рядка `[demo] веб-панель: http://127.0.0.1:8000` (≈ 25 с,
   поки завантажуються моделі). У шапці панелі має бути «31/31 на
   зв'язку».
5. Сказати пробну команду («Телекінез» → сигнал → «увімкни світло на
   кухні»), потім вимкнути світло. На вкладці «Збої» натиснути «Скинути
   всі».
6. Браузер — на весь екран (F11), масштаб 100–110 %, щоб на проєкторі було
   видно плитки й праву панель з відповідями.

Зупинити все після захисту — Ctrl+C у вікні PowerShell.

## Хід показу

### 1. Звичайні команди (≈ 1 хв)

Говорити: «Телекінез», дочекатися короткого сигналу, потім команду. Замість
ключового слова можна тримати правий Ctrl.

| Команда | Відповідь асистента | Що показати |
|---|---|---|
| увімкни світло на кухні | «Світло на кухні увімкнено.» | плитка змінюється одразу; праворуч — розпізнаний текст і намір |
| відкрий штори у вітальні | «Штори у вітальні відкрито.» | смуга штор рухається кілька секунд — відповідь лише після того, як штори реально відкрились |
| turn on the bathroom light | «Bathroom light is on.» | англійська: відповідь тією самою мовою |
| вимкни все світло | «Вимкнено 11 пристроїв.» | групова команда: одна фраза — 11 команд, кожна з контролем |
| чи все світло вимкнено? | «Так, усе вимкнено.» | запит стану: відповідь із цифрового двійника, без команди пристроям |
| what is the temperature in the bedroom | «Bedroom sensor: temperature 21.0 °C.» | показ датчика |

Коментар: «Асистент не каже "готово", доки пристрій сам не повідомить, що
його стан збігся з бажаним».

### 2. Збої (≈ 1,5 хв, головне)

Перейти на вкладку **«Збої»**:

1. «Замок вхідних дверей» → `offline` → «Застосувати». Майже одразу
   праворуч з'являється сповіщення «Замок вхідних дверей не на зв'язку» (брокер
   публікує «останній заповіт» пристрою).
2. «Штори у вітальні» → `stuck` → «Застосувати» (пристрій приймає команду,
   але двигун «заклинило»).

Повернутися на **«Пристрої»** і сказати:

| Команда | Відповідь асистента | Кінцевий стан | Що пояснити |
|---|---|---|---|
| відчини вхідні двері | «Замок вхідних дверей зараз не в мережі.» | DEVICE_OFFLINE | команда навіть не відправлялась — асистент знає, що пристрій недоступний |
| закрий штори у вітальні | «Штори у вітальні: команду прийнято, але стан не змінився.» (через ≈ 6 с) | TIMEOUT_STATE | пристрій підтвердив прийом, але штори не рушили; на плитці — «Не виконує» |

Звичайний асистент в обох випадках сказав би «Готово».

### 3. Журнал (≈ 30 с)

Вкладка **«Журнал»**: кожна команда зі статусом і часом етапів (публікація
→ підтвердження → збіг стану). Показати рядки DEVICE_OFFLINE і
TIMEOUT_STATE, у звичайних командах — підтвердження за ~60 мс.

Наприкінці: вкладка «Збої» → «Скинути всі».

### Додатково, якщо питають (≈ 30 с)

- **«Пристрій мовчить»**: на «Збоях» вибрати для світла `freeze`, сказати
  «увімкни світло у спальні» → після трьох спроб (≈ 7,5 с) відповідь, що
  світло у спальні не відповідає (TIMEOUT_ACK).
- **Zigbee-штори** («Штори у спальні», протокол Zigbee2MQTT): з `stuck`
  дадуть «не відповідають», а не «стан не змінився», — у цієї прошивки
  немає окремого підтвердження (обмеження, описане в розділі 4).
- **Налаштування**: перемкнути розпізнавання Vosk ↔ Whisper без
  перезапуску.

## План Б

| Що сталося | Що робити |
|---|---|
| Мікрофон не чує / шум в аудиторії | Ті самі команди ввести в поле «Напишіть команду…» праворуч на панелі (Enter) — це той самий шлях, що й голос, лише без розпізнавання |
| Асистент не стартує з голосом | Ctrl+C і `powershell -ExecutionPolicy Bypass -File scripts\demo.ps1 --no-voice` — лише веб-панель з текстовим вводом |
| Немає звуку з динаміка | Відповіді видно текстом у правій панелі; продовжувати |
| Не стартує брокер / нічого не працює | Показати відео `presentation/demo.mp4` (74 с, той самий сценарій текстом) — відкрити заздалегідь у плеєрі; запасна копія — `docs/img/demo.gif` |
| Порт 8000 зайнятий | Закрити попередній запуск (Ctrl+C у його вікні) або перезавантажити ноутбук |

Відео перезаписується однією командою (потрібні `pip install playwright
imageio-ffmpeg` і `python -m playwright install ffmpeg`):

```bash
python presentation/record_demo.py
```
