# Специфікація: експерименти і метрики

Результати потрапляють у розділ 4 записки і презентацію **лише якщо отримані
реальними запусками**. Кожен скрипт пише `benchmarks/results/<name>_<date>.csv`
і будує графік `*.png` (matplotlib, чорно-біло-друкований стиль, підписи
українською).

## 1. Набори даних

| Набір | Як отримати | Обсяг |
|---|---|---|
| `datasets/voice/` — записи команд | `scripts/record_dataset.py`: показує фразу, автор читає, файл WAV 16 kHz + мітка | 60–100 фраз uk + 30–50 en; бажано 2–3 різні голоси (друзі/родина) |
| `datasets/voice_synth/` | ті самі фрази, озвучені Piper (TTS→STT) | автоматично; лише як додатковий, позначати окремо |
| `datasets/nlu_commands.yaml` | вручну + генерація варіантів | ≥ 200 фраз |
| `datasets/noise/` | 10–15 хв фонового аудіо (розмова, музика, TV) | для false accept wake word |

## 2. Експерименти

| # | Скрипт | Що порівнюємо | Метрики |
|---|---|---|---|
| E1 | `run_stt.py` | Vosk (вільний) · Vosk (граматика) · Whisper small/medium (GPU, CPU) | WER, CER, точність команд (після NLU), RTF, затримка p50/p95 |
| E2 | `run_nlu.py` | RuleParser · LlmParser · hybrid | accuracy наміру, точність слотів (дія/пристрій/кімната/параметр), затримка |
| E3 | `run_latency.py` | повний ланцюжок у текстовому і голосовому режимі | розкладка затримки: VAD-кінець → транскрипт → намір → publish → ack → completed → початок TTS |
| E4 | `run_faults.py` | сценарії з `fault_scenarios.yaml` × N повторів | частка виявлених збоїв, час виявлення, частка відновлених повтором, хибні тривоги |
| E5 | `run_wakeword.py` | vosk_kws · openwakeword | false reject rate на записах, false accepts / год на фоні |
| E6 | `run_scale.py` | 10 / 25 / 50 / 100 симульованих пристроїв | затримка ack, CPU/RAM асистента |

**Умови для E2 (LLM).** Затримка LlmParser різко залежить від того, чи
поміщається модель у відеопам'ять: на RTX 3060 6 ГБ із запущеною грою
`qwen2.5:3b` працювала на 95 % CPU (2,6–4,9 с на запит). Перед вимірами
закрити програми, що займають GPU, перевірити `ollama ps` (колонка PROCESSOR
має показувати GPU) і записати це в умови експерименту.

## 3. Вимоги до звіту про експеримент

Для кожного: умови (залізо, версії моделей, налаштування), кількість
прогонів, таблиця, графік, короткий висновок. Якщо результат поганий —
пишемо чесно і пояснюємо причину; це теж матеріал для висновків.
